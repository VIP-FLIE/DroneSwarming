# Worlds

The blank grey ground is PX4's `default.sdf`: a flat plane and one light.

A map in Gazebo is a world (one `.sdf` file). Your code does not change. The world is a Gazebo concern. PX4 publishes the same topics. `ros2 run cpp_single_hop hop` behaves identically in all worlds.

## Fly in a world PX4 ships

One environment variable, no rebuild:

```bash
cd ~/PX4-Autopilot
PX4_GZ_WORLD=lawn PX4_SIM_MODEL=gz_x500 ./build/px4_sitl_default/bin/px4
```

Agent, `drone-gcs`, then your node in the fourth terminal, as in [HOW-IT-WORKS.md](HOW-IT-WORKS.md).

PX4 v1.16.1 ships ten worlds in `~/PX4-Autopilot/Tools/simulation/gz/worlds/`.

| `PX4_GZ_WORLD=` | Contents | Notes |
|---|---|---|
| `default` | Flat grey plane, one sun | Default when variable is unset |
| `lawn` | Green ground, sky, grid | Low render cost |
| `walls` | Four boxes around origin | Obstacles, motion reference |
| `windy` | Flat plane, 5.4 m/s wind | Controller test |
| `forest` | Trees and grass | Downloads from Fuel on first run |
| `baylands` | Park and coastline, real terrain | Downloads from Fuel, slowest to load |
| `aruco` | Flat plane with ArUco marker | For `gz_x500_mono_cam` |
| `moving_platform` | Platform that drives away | Landing on moving target |
| `rover` | Ground for wheeled vehicles | 500 Hz physics |
| `frictionless` | Zero friction ground | Broken in v1.16.1 |

`forest` and `baylands` pull models from [Gazebo Fuel](https://app.gazebosim.org/fuel) on first launch. Needs internet. Cached in `~/.gz/fuel` after.

`frictionless` does not start. File is `frictionless.sdf`, world inside is named `default`. PX4 looks up by file name. Prints `Waiting for Gazebo world...` 30 times and exits.

### Running your package in one

Only terminal 3 changes:

```bash
MicroXRCEAgent udp4 -p 8888              # 1
drone-gcs                                # 2
cd ~/PX4-Autopilot                       # 3
PX4_GZ_WORLD=walls PX4_SIM_MODEL=gz_x500 ./build/px4_sitl_default/bin/px4
ros2 run cpp_single_hop hop              # 4
```

`hop` takes off, flies 3 m forward, lands in `walls` as in `default`. `hop` contains no obstacle avoidance. Pointing it at a pillar flies it into one. Gazebo simulates the collision; PX4 does not know the wall is there.

## What PX4 does with that variable

PX4's startup script (`ROMFS/px4fmu_common/init.d-posix/px4-rc.gzsim`) does:

```sh
gz sim -r -s "$PX4_GZ_WORLDS/$PX4_GZ_WORLD.sdf"     # line 54
```

Waits for a running world by name:

```sh
gz service -i --service "/world/${PX4_GZ_WORLD}/scene/info"    # line 80
```

Two constraints:

1. World name and file name must match. Mismatch: 30-second hang then exit.
2. World must be in PX4's worlds directory. `$PX4_GZ_WORLDS` is set by `build/px4_sitl_default/rootfs/gz_env.sh` at build time. `scripts/install-worlds.sh` symlinks worlds into that directory.

Value source, last one wins:

| Source | Example | Use |
|---|---|---|
| Airframe default | `4001_gz_x500` sets `PX4_GZ_WORLD=${PX4_GZ_WORLD:=default}` | Fallback |
| Make target | `make px4_sitl gz_x500_lawn` | Rarely |
| Environment | `PX4_GZ_WORLD=lawn PX4_SIM_MODEL=gz_x500 ./build/px4_sitl_default/bin/px4` | Always |

Make targets are generated by globbing the worlds directory at CMake configure time. A world added today needs a PX4 reconfigure for a target. The environment variable needs no rebuild.

## Writing your own world

[`../../worlds/vip_field.sdf`](../../worlds/vip_field.sdf) is a worked example: grass, four pillars on a 20 m square, landing pad, two instances of a local model. Every block is commented.

```bash
./scripts/install-worlds.sh          # link worlds into PX4
cd ~/PX4-Autopilot
PX4_GZ_WORLD=vip_field PX4_SIM_MODEL=gz_x500 ./build/px4_sitl_default/bin/px4
```

Start your own:

```bash
cp worlds/vip_field.sdf worlds/your_world.sdf
```

1. **Rename the world inside the file.** `<world name="your_world">` must match the file name. `install-worlds.sh` refuses a mismatch.
2. Edit contents. `<pose>x y z roll pitch yaw</pose>`, metres and radians, ENU: `+y` north, `+z` up.
3. Validate XML:
   ```bash
   gz sdf -k worlds/your_world.sdf
   ```
   Prints `Valid.` or the line number. Does not resolve `model://` URIs.
4. Link and fly:
   ```bash
   ./scripts/install-worlds.sh
   cd ~/PX4-Autopilot
   PX4_GZ_WORLD=your_world PX4_SIM_MODEL=gz_x500 ./build/px4_sitl_default/bin/px4
   ```

`install-worlds.sh` symlinks. After first run, editing the file in this repo is enough. No colcon build, no PX4 rebuild.

`./scripts/install-worlds.sh --list` shows what PX4 can load and which are ours.

### Four physics elements the flight code feels

Everything else in an SDF world is scenery. These four are physics.

| Element | Value to keep | What breaks if changed |
|---|---|---|
| `<max_step_size>` and `<real_time_update_rate>` | `0.004` and `250` | PX4 lockstep. Different step rate changes estimator and controller feed rate |
| `<gravity>` | `0 0 -9.8` | Hover throttle and every tuned gain |
| `<magnetic_field>` | Must match coordinates | EKF2 declination table disagrees, yaw drifts |
| `<spherical_coordinates>` | Real place, `world_frame_orientation` ENU | PX4 reports GPS from it, sets home from it |

Moving a world to a real location: update both coordinates and magnetic field. Get declination (D), inclination (I) and total field (F) from [NOAA magnetic field calculator](https://www.ncei.noaa.gov/products/geomagnetic-calculators). With F in tesla:

```
east  = F * cos(I) * sin(D)
north = F * cos(I) * cos(D)
up    = -F * sin(I)
```

Write those three into `<magnetic_field>` in that order. `vip_field.sdf` uses PX4's own Zurich coordinates and field vector (a known-consistent pair).

### Minimum world

Strip `vip_field.sdf` down. What must survive:

- `<physics>`, `<gravity>`, `<magnetic_field>`, `<atmosphere>`
- One light (or scene is black)
- A ground plane (or drone falls forever)
- `<spherical_coordinates>`
- `<scene>` optional. `<sky/>` adds horizon for attitude reference

## Models

Three ways to get geometry into a world.

**Inline shapes.** Boxes, spheres, cylinders, planes directly in the world file. Right for a few primitives.

**Make a model.** Directory with `model.config` and `model.sdf`. [`../../worlds/models/goal_marker/`](../../worlds/models/goal_marker/) is a minimal example. Put yours in `worlds/models/`, run `./scripts/install-worlds.sh`. Bare name resolves:

```xml
<include>
  <uri>model://goal_marker</uri>
  <name>goal_north</name>
  <pose>0 25 0 0 0 0</pose>
</include>
```

`<name>` is required when including the same model twice. Two entities with the same name: second silently does not appear.

The script links `worlds/models/*/` into PX4's models directory (already on `GZ_SIM_RESOURCE_PATH`). Mesh goes in the model directory (`meshes/*.dae` or `.stl`), referenced as `<uri>model://your_model/meshes/thing.dae</uri>`. Keep collision geometry a crude box or cylinder. Collision meshes are expensive; a swarm multiplies cost.

**From Fuel.** [app.gazebosim.org/fuel](https://app.gazebosim.org/fuel):

```xml
<include>
  <uri>https://fuel.gazebosim.org/1.0/OpenRobotics/models/Pine Tree</uri>
  <pose>12 -8 0 0 0 0</pose>
</include>
```

First load downloads. Cached in `~/.gz/fuel`. A world with fifty Fuel models takes a long first launch and needs internet. Commit nothing from `~/.gz/fuel`.

## Building a world by clicking

1. Open the world in Gazebo without PX4:
   ```bash
   gz sim worlds/vip_field.sdf
   ```
2. Add Resource Spawner: vertical dots top right → `Resource Spawner`. Lists local models and Fuel. Drag into scene.
3. Move/rotate with toolbar tools. Component Inspector shows exact pose.
4. Save with `Save world as` into `worlds/`.
5. **Read the saved file before flying.** Check `<world name=>` matches file name and `<physics>` block says `0.004` and `250`.

A saved file is more verbose than hand-written. Trim it.

## Worlds and swarms

Every vehicle shares one world. Only the first launch creates it. `px4-rc.gzsim` looks for a running world before starting one.

- Set `PX4_GZ_WORLD` on the first instance. Later instances join whatever is running. A different value on the second is ignored.
- Let the first finish loading before the second. Large worlds can take a minute.
- Spawn positions from `PX4_GZ_MODEL_POSE` in ENU metres. Check against obstacles. Spawning inside geometry makes Gazebo shove the drone out at speed.

```bash
PX4_GZ_WORLD=vip_field PX4_SYS_AUTOSTART=4001 PX4_SIM_MODEL=gz_x500 \
  ./build/px4_sitl_default/bin/px4 -i 1
PX4_GZ_MODEL_POSE="0,3" PX4_SYS_AUTOSTART=4001 PX4_SIM_MODEL=gz_x500 \
  ./build/px4_sitl_default/bin/px4 -i 2
```

Scenery costs. Every Fuel tree, collision mesh and shadow is work. With eight vehicles, RTF is what pays. Fly swarms in `default` or `vip_field`. Save `baylands` for demos. `HEADLESS=1` removes rendering cost, physics unchanged.

## Problems

| Symptom | Cause | Fix |
|---|---|---|
| `Waiting for Gazebo world...` then `Timed out` | `<world name>` doesn't match file name | Make them match. `install-worlds.sh` catches this |
| `Starting gazebo with world: .../yours.sdf` then exits | File not there | `./scripts/install-worlds.sh` |
| Gazebo opens world chooser with Prius | Ran `gz sim` with no arguments | `PX4_SIM_MODEL=gz_x500 ./build/px4_sitl_default/bin/px4` |
| World loads, models missing, `Unable to find uri` | Model not on resource path | `./scripts/install-worlds.sh`, check `--list` |
| First launch of `forest`/`baylands` hangs | Fuel download | Wait with internet. Cached after |
| Drone launches sideways at spawn | Spawned inside geometry | Move `PX4_GZ_MODEL_POSE` or obstacle |
| Yaw drifts, `mag` warnings in moved world | `<magnetic_field>` doesn't match coordinates | Recompute both |
| RTF drops below 1 with swarm | Rendering and collision cost | `HEADLESS=1`, simpler world, box collisions |
| World vanished after PX4 reinstall | Links went with PX4 tree | `./scripts/install-worlds.sh` |
| `git status` in `~/PX4-Autopilot` shows untracked files | Our symlinks in PX4 submodule | Expected. `--remove` takes them out |
