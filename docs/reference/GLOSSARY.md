# Glossary

This glossary defines terms and abbreviations used in the repository's code and guides. It includes expansions when the source name is known and identifies project or product names that are not acronyms.

## A

- **Action:** A ROS 2 request for work that can take time and report feedback, a result, and cancellation. This repository uses actions for takeoff, navigation, landing, and mission execution. See the [ROS 2 action concepts](https://docs.ros.org/en/jazzy/Concepts/Basic/About-Actions.html).
- **API (Application Programming Interface):** The types and operations that software exposes for other software to use. In this repository, ROS messages and actions are part of the application API.

## C

- **clangd:** The C and C++ language server used by the editor guides. It provides diagnostics, completion, hover information, and code navigation.
- **Companion computer:** A computer that runs alongside the flight controller and hosts higher-level software. In this project, ROS 2 application nodes and the XRCE-DDS agent run in the development environment.
- **Compilation database:** The `compile_commands.json` file generated by the build. It records compiler commands so tools such as `clangd` can use the project's include paths, defines, and compiler options.

## D

- **DDS (Data Distribution Service):** A publish-subscribe middleware standard used by ROS 2. PX4 exposes selected internal messages to ROS 2 through the XRCE-DDS bridge. See the [PX4 v1.17 DDS topic list](https://docs.px4.io/v1.17/en/middleware/dds_topics).

## E

- **ENU (East-North-Up):** A local coordinate frame whose X axis points east, Y axis points north, and Z axis points up. Application positions use `local_enu` and are measured in meters from PX4's local-position origin.

## F

- **FMU (Flight Management Unit):** The flight-controller hardware that runs the flight stack. In PX4 ROS 2 topic paths, `/fmu` is the standard topic-prefix segment; a vehicle-specific prefix can appear before it, such as `/uav_1/fmu`. See the [Pixhawk hardware project](https://github.com/Pixhawk/Hardware) and [PX4 topic namespace guide](https://docs.px4.io/v1.17/en/middleware/uxrce_dds).

## G

- **Gazebo Harmonic:** The Gazebo simulator release used by this repository's development environment. It simulates the vehicle, sensors, physics, and world.
- **GCS (Ground Control Station):** Software used to monitor and operate a vehicle. QGroundControl is this repository's ground control station.

## L

- **LLM (Large Language Model):** A model that generates or transforms text and code. The repository's coding rules apply to LLM-generated changes.
- **LSP (Language Server Protocol):** A protocol that lets an editor communicate with a language server for features such as diagnostics, completion, hover information, and code navigation.
- **Local-position origin:** PX4's reference point for local position estimates. Application `local_enu` coordinates are measured from this point. Mission waypoint offsets are measured from the position captured when the mission starts.

## M

- **MAVLink:** A lightweight message protocol and library for communication between vehicles, onboard components, and ground stations. The upstream project names it the **Micro Air Vehicle Message Marshalling Library**. See the [MAVLink project](https://github.com/mavlink/mavlink).
- **Mission origin:** The vehicle position captured at mission start. Every waypoint offset in a mission is added to this same position.

## N

- **Namespace:** A prefix that scopes ROS 2 node and interface names. The application namespace and PX4 topic prefix are separate settings in this repository.
- **NED (North-East-Down):** A local coordinate frame whose X axis points north, Y axis points east, and Z axis points down. PX4 local positions and trajectory setpoints use this frame.

## O

- **Offboard mode:** A PX4 flight mode that accepts setpoints from an external controller, such as a ROS 2 application. PX4 requires a continuing Offboard control signal while this mode is active. See the [PX4 v1.17 Offboard guide](https://docs.px4.io/v1.17/en/flight_modes/offboard).

## P

- **PX4:** The name of the open-source flight-control project and stack used in this repository. It is a project name, not an acronym expanded here.
- **`px4_msgs`:** The ROS 2 package containing message definitions for PX4 interfaces. Its version must match the PX4 firmware message definitions used by the project.

## Q

- **QGroundControl (QGC):** A ground control application for configuring and monitoring vehicles. This repository runs it on the Linux host and connects it to PX4 over MAVLink and UDP.
- **QoS (Quality of Service):** ROS 2 communication settings that control delivery behavior, including reliability, history, and durability. Publishers and subscribers need compatible QoS settings to communicate. See the [ROS 2 QoS concepts](https://docs.ros.org/en/jazzy/Concepts/Intermediate/About-Quality-of-Service-Settings.html).

## R

- **RAII (Resource Acquisition Is Initialization):** A C++ ownership idiom that ties a resource's lifetime to an object's lifetime. When the object leaves scope, its destructor releases the resource.
- **ROS (Robot Operating System):** A robotics software ecosystem. Despite the name, ROS is not an operating system.
- **ROS 2:** The second generation of ROS. This repository targets the Jazzy release.
- **ROS 2 node:** A unit of computation that uses the ROS graph to communicate with other nodes. See the [ROS 2 node concepts](https://docs.ros.org/en/jazzy/Concepts/Basic/About-Nodes.html).
- **ROS 2 topic:** A named stream of typed messages. Publishers send messages to a topic, and subscribers receive them. See the [ROS 2 topic concepts](https://docs.ros.org/en/jazzy/Concepts/Basic/About-Topics.html).

## S

- **Setpoint:** A desired position, velocity, or other control value that a controller attempts to reach or maintain.
- **SITL (Software In The Loop):** A simulation setup that runs the autopilot software against a simulated vehicle instead of flight-controller hardware. This repository runs PX4 SITL with Gazebo.

## T

- **Telemetry:** Vehicle state data reported by the flight stack, such as position, armed state, landing state, and battery level.

## U

- **UDP (User Datagram Protocol):** A network transport used by the project for XRCE-DDS communication and the QGroundControl MAVLink connection.
- **uORB:** PX4's internal publish-subscribe message system. The XRCE-DDS client bridges selected uORB messages to ROS 2.
- **uXRCE-DDS / Micro XRCE-DDS:** The PX4 bridge that uses eProsima's Micro XRCE-DDS implementation to connect resource-constrained clients to a DDS network. PX4 runs the client, and the companion computer runs the agent. **XRCE** refers to DDS for eXtremely Resource Constrained Environments. See the [PX4 bridge guide](https://docs.px4.io/v1.17/en/middleware/uxrce_dds) and [eProsima Micro XRCE-DDS documentation](https://micro-xrce-dds.docs.eprosima.com/en/latest/).

## X

- **X500:** The stock PX4 multicopter model used by this repository's Gazebo simulation. It is a model name, not an acronym.
